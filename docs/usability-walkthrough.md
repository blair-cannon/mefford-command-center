# Employee usability walkthrough

Status: prepared; employee observation has not been performed.

Use an isolated test project and representative records. Each participant uses
their normal role, usual device, and current permissions. Give the task without
pointing out buttons. Observe silently, then ask what caused hesitation.

| Participant | Task | Success evidence |
| --- | --- | --- |
| Superintendent | Open the assigned job, start a daily log, add a photo, save a device draft, leave and resume it. | Correct job and date; description and original photo restored; understands the draft has not been submitted. |
| Project manager | Find a drawing and an overdue RFI; open the source task; find the next responsible person. | Correct revision and job; source opens directly; no coaching needed. |
| Estimator | Find an estimate due soon, open its bid coverage, and locate the next approval requirement. | Correct estimate; missing quotes and required review recognized. |
| Accountant | Find an invoice awaiting review and identify the evidence and next approval. | Correct project and amount; no payment or posting performed in testing. |
| Company owner | Filter the approval queue, inspect an exception, and locate its evidence. | Filter and selected packet agree; failed checks are understood. |
| Less technical employee | Find a daily tool through All Tools, pin it, and find it again after reopening. | Tool found without knowing the department menu; preference retained. |

Capture task completion, elapsed time, wrong turns, requests for help, incorrect
project selection, and whether the participant correctly describes the save or
submission state. Do not record passwords or private employee content.

Acceptance targets: at least 90% of tasks completed without coaching; zero
wrong-project submissions; every participant understands device draft versus
uploaded record. Review keyboard-only navigation, 200% browser zoom, and a phone
viewport. Keep all information available through vertical reflow.

For every observed failure, record the exact screen, the action attempted, the
expected result in the participant's words, and the proposed correction. Repeat
only the failed task after correction. Keep actual results separate from targets.
