# Main Command Center interface review

This change addresses readable controls, overlapping layers, and responsive layout in the main Command Center. It does not change accounting calculations, authorization rules, or external integrations.

## Changes

- Added a final, screen-only stylesheet for shared controls and focused workspace corrections. Text, form controls, metadata, focus outlines, tabs, and action groups use readable sizes and flexible spacing.
- Restored neutral gray and Mefford red styling in the shared shell and accounting dashboard. Corrected the accounting hero's dark-on-dark heading.
- Kept all six company dashboard cards and all three lower panels visible together on desktop. Metrics stack their labels above their values; overflowing record regions scroll independently. Truncated metric labels and values expose their full text through titles.
- Reserved space for the mobile connectivity bar and kept standard dialogs above mobile navigation and floating controls. Preserved the compact accounting header's icon button without letting its hidden text overflow.
- Gave the estimate editor a fixed header and footer with a scrolling middle region. The cost-code grid owns its horizontal and vertical scrolling; Save and Submit remain visible on small screens.
- Enlarged sales, calendar, project overview, employee home, approval, accounting, schedule, quality, safety, and administration labels and controls. Calendar and quality dialogs now have explicit accessible names and labeled close buttons.

## Browser review

Reviewed the managed local preview using isolated synthetic records, including a long project/company name and a $9,876,543.21 pipeline value. No live records or integration settings were changed.

DOM checks measured viewport and page widths, text sizes, visible overflow, dashboard panel bounds, and estimate footer bounds. Screenshots were inspected alongside those measurements. Calendar and ledger horizontal scrolling, as well as the schedule's narrow Today marker, are intentional.

This is a visual and control-layout review of the shared shell and representative workflows. It does not certify every populated record state, external integration, touch-device keyboard, or production data combination. Existing release checks remain the required regression gate.

The release run exposed a pre-existing midnight-boundary assumption in the payroll audit: its UTC pay-date fixtures were being compared against the report's default Eastern date. The audit now requests the fixture's pay date explicitly and retains the same payroll, rollback, duplicate, and approval assertions. Production reporting and payroll code are unchanged.
